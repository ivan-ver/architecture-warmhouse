Warm House - это распределённая система управления умными устройствами, построенная на микросервисной архитектуре. Система предоставляет пользователям (как конечным пользователям, так и администраторам) широкие возможности по управлению устройствами, мониторингу состояния, получению уведомлений и анализу данных. Основной акцент сделан на гибкости, масштабируемости и интеграции с внешними системами уведомлений и авторизации.

* Роли пользователей
    - User
        Обычный пользователь (житель дома).
        Использует мобильное или веб-приложение.
        Может управлять подключёнными устройствами, просматривать историю измерений, получать уведомления.
        Имеет настройки приоритетов каналов уведомлений (SMS, Email, Push).
    - Admin
        Администратор системы.
        Работает через веб-приложение.
        Отвечает за создание и управление пользователями, конфигурацию системы, наблюдение за состоянием инфраструктуры.

* Клиентские приложения
    - Мобильное приложение
        Платформы: Android и iOS.
        Предоставляет интерфейс для управления устройствами, получения уведомлений и мониторинга состояния дома.
        Работает с системой через API Gateway.
    - Веб-приложение
        Стек: Angular / React + Node.js.
        Универсальный интерфейс для пользователей и администраторов.
        Предоставляет аналогичный функционал с поддержкой адаптивного дизайна и полноценного рабочего интерфейса.

* Архитектура и основные компоненты
    - API Gateway
        Реализован с помощью Spring Cloud Gateway.
        Единственная точка входа для всех клиентских запросов.
        Выполняет маршрутизацию запросов, проверку авторизации через Keycloak и может реализовывать политику безопасности.
    - User Service
        Реализован на Spring Boot.
        Обрабатывает данные пользователей: регистрация, логин, профиль.
        Взаимодействует с Keycloak для авторизации и получения JWT-токенов.
        Хранит информацию в PostgreSQL.

* Admin Service
    - Отвечает за административные функции.
    - Предоставляет интерфейс и API для управления пользователями, устройствами и политиками уведомлений.
    - Имеет свою БД (PostgreSQL) и публикует события в Kafka для других компонентов.

* Device Service
    - Центральный сервис взаимодействия с устройствами.
    - Управляет метаданными устройств.
    - Перенаправляет запросы по ID устройства в соответствующие специализированные сервисы:
        Sync Devices Service (синхронные устройства),
        Async Devices Service (асинхронные устройства),
        Control Service (устройства управления).
    - Публикует события в Kafka в случае аномалий или поломок.

* Устройства и их обслуживание
    - Sync Devices Service
        Работает с синхронными устройствами (например, проводные датчики).
        Получает данные только по запросу (pull-модель).
        Может сохранять историю в базу (в том числе передавать в Time Series Service).
    - Async Devices Service
        Работает с асинхронными устройствами (например, беспроводные датчики).
        Принимает данные по WebSocket в режиме реального времени.
        Публикует эти данные в Kafka (топик показаний).
    - Control Service
        Управляет активными устройствами: реле, умные розетки, контроллеры.
        Отправляет команды внешним системам через REST API.
        Используется как веб-интерфейс, так и API-запросы из Device Service.

* Обработка и хранение данных
    - Time Series Service
        Обрабатывает данные от асинхронных устройств (через Kafka).
        Сохраняет данные во временные ряды.
        Использует ClickHouse как хранилище, обеспечивающее высокую производительность при чтении и агрегации данных.

* Система уведомлений
    - Notification Service
        Получает события через Kafka (например, неисправности устройств или тревоги).
        Обогащает события пользовательскими данными (через User Service).
        Отправляет уведомления с учётом приоритета канала:
            SMS (через внешнюю SMS-систему, протокол SMPP),
            Push (через Firebase, Apple SDK),
            Email (через SMTP/IMAP).
        Канал доставки определяется настройками профиля пользователя.

* Безопасность и авторизация
    - Keycloak
        Внешняя система авторизации.
        Предоставляет JWT-токены для пользователей.
        Интеграция через OpenID Connect.
        Используется всеми сервисами для валидации доступа.

* Интеграции и взаимодействие
   - Kafka - ключевой брокер сообщений. Используется для передачи событий между микросервисами, обработки данных от устройств и нотификаций.
   - Внешние системы подключаются через REST или WebSocket:
   - Async Devices - взаимодействие по WebSocket.
   - Sync Devices - взаимодействие по REST.
   - Control System - управление устройствами через REST.
   - Системы уведомлений (SMS, Push, Email) - через REST/SMTP/SMPP.

* Используемые базы данных
     Сервис	                Тип БД      Назначение
     User Service	        PostgreSQL	Хранение данных о пользователях
     Admin Service	        PostgreSQL	Данные об администраторах, настройках
     Device Service	        PostgreSQL	Справочник устройств
     Time Series Service	ClickHouse	История показаний асинхронных устройств

│   ├── Device Service
│   │   ├── PostgreSQL (справочник устройств)
│   │   ├── Sync Devices Service

│   │   ├── Async Devices Service

│   │   │   └── Kafka (публикация событий)

│   │       └── REST-интеграции (управление устройствами)
